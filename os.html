L8 仮想記憶の管理(2)：置換え技法 Replacement Techniques

記憶管理技術の3分類

フェッチ技法fetch technique いつ主記憶上に読み出すかに関する技術。要求時フェッチ（demand fetch）とプリフェッチ（prefetch）がある。 「何时」把页面调入主存。分「按需取（demand）」和「预取（prefetch）」。 割付け技法placement technique 主記憶上のどこに読み出すかに関する技術（4章の内容）。 「放在哪里」——决定调入主存的位置。 置き換え技法replacement technique 主記憶上のどこを追い出すかに関する技術。今回の主題。 「换出谁」——决定把主存哪一页赶出去。本讲重点。

ページ置換えアルゴリズム

選択基準：ページフォールト率（page fault rate）＝ページフォールト発生回数 ÷ 仮想記憶参照回数。この率が最小になるアルゴリズムを選ぶ（※「最大」は誤り、頻出ひっかけ）。参照列は参照ストリング（reference string）という。
缺页率＝缺页次数÷虚存访问次数，选缺页率最小的算法（「最大」是陷阱）。访问序列叫 reference string。
算法日文原文 / 说明中文
FIFOFirst In First Out。最も古いページ（最初に入ったページ）を退場させる。キューで管理し、新ページはキュー末尾につなぐ。最先进先出，换出最老的页
OPT
(optimal)		参照ストリングの将来の知識を利用し、最も遠い将来に必要とされるページを追い出す。最小のページフォールト数を与えるが実現困難（将来予測が難しい）。比較用の基準として使う。最优：换出「未来最晚才用」的页；缺页最少但无法实现，只作基准
LRU
(Least Recently Used)		最も長い期間使用されていないページを退場させる。多くのシステムで利用。ハードウェアのサポートが必要（ソフトのみでは厳密に実現できない）。最近最少使用：换出最久没用的页；需硬件支持
Belady の異常（FIFO異常）Belady's anomaly 一般にページ枠を増やすと性能向上が期待できるが、FIFOではページ枠を増やすと逆にページフォールトが増えることがある現象。「Beladyの異常」または「FIFO異常」と呼ぶ（綴りに注意：Berady は誤り）。 通常增加页框（page枠）能提升性能，但 FIFO 中增加页框反而缺页更多的现象。写法要准确。
LRU の実現方法：①カウンタ（HW：各ページの最終参照時刻を記録、最小時刻を削除）②スタック（HW：参照されたページ番号を上へ、底のページを削除）③参照ビット（SW近似、定期的に見てソフトウェアカウンタ更新 → これは NFU：Not Frequently Used という）。
LRU 三种实现：计数器/栈（硬件），参照位（软件近似，即 NFU）。

割付けと置換えの範囲

大域置換えglobal replacement すべてのページ枠から置き換えるページを選択。各プロセスが自分のページフォールト率を制御できない。 从所有页框里选换出页；进程无法控制自己的缺页率。 局所置換えlocal replacement そのプロセスに割り付けられたページ枠の中で置き換えるページを選択。 只在本进程分到的页框内选换出页。

マルチプログラミングの割付けアルゴリズム：均等割り付け（各プロセスに同じ枠 p/n、p=有効ページ枠数、n=プロセス数）、比例配分割付け（仮想記憶の大きさで比例配分）、優先度を考慮した割付け。均等/按比例/按优先级 三种分配。

スラッシングと局所性

スラッシングthrashing ページフォールトが頻繁に発生し、処理が進まない状態。悪循環：多重度増加→各プロセスがページ枠要求→ページフォールト→2次記憶読出し→CPU利用率低下→さらに多重度増加。対応：多重度を下げる。回避策：十分な主記憶、多重度を上げない。 缺页频繁、处理停滞的状态。多道度↑→缺页→读二级存储→CPU利用率↓→又加进程 的恶性循环。对策：降多道度；避免：足够主存、不过度增加多道度。
参照の局所性locality of reference 時間的局所性：最近参照されたページは近い将来にも参照される確率が高い（ループ・サブルーチン・スタック・カウンタ）。空間的局所性：あるページが参照されると近くのページも参照される確率が高い（配列スキャン・逐次実行）。 时间局部性：刚访问的页不久会再访问；空间局部性：访问某页则邻近页也易被访问。

ワーキングセット

ワーキングセットworking set プロセスが現在使っているページの集合。ワーキングセット W(t, w)＝ウィンドウ [t−w, t] の間に参照されるページの集合。仮想時間（当該プロセスのみが実行される時間）上にウィンドウサイズ w を設定する。 进程当前正在使用的页集合。W(t,w)=在窗口[t−w,t]内被引用的页集合；窗口设在「虚拟时间」（只算该进程运行的时间）上。
ウィンドウサイズの選択（順序が頻出）：
・小さすぎる → ワーキングセットを取り込めない → ページフォルト多発 → スラッシング
・大きすぎる → 複数のワーキングセット取込み → 不要な情報が主記憶上に存在 → 主記憶を圧迫 → ページフォルト多発 → スラッシング
窗口太小或太大都会 →最终缺页多发→抖动。大的情况顺序：多个工作集被取入→存在多余信息→压迫主存→缺页多发→抖动。

ワーキングセット法の特徴 — 長所：参照の局所性を活かし効率がよい、プロセス特性・状態に応じた割付けが可能。短所：ウィンドウサイズの決定が難しい、ワーキングセットの予測が難しい。

L9 ファイルシステム(1) File System

ファイルの必要性と定義

ファイルシステムが必要な理由：①仮想アドレス空間に収まらない大容量情報を扱う ②プロセス終了後も情報を保存する ③複数プロセスが同時にアクセスできる。ファイルシステムは2次記憶を抽象化する。
文件系统的必要性：大容量、持久保存、多进程共享；它把二级存储抽象化。
ファイルfile 関連のある情報の集まり又はその入れ物。データあるいはプログラムの名前付けられた集合であり、それらを格納するための論理的な単位。 相关信息的集合，是有名字的数据/程序集合，是存储的逻辑单位。
拡張子extension ファイルの種類を示す3〜4文字の文字列。MS-DOS（Windowsのもと）では3文字までの制限があった（今は制限緩和）。 扩展名，表示文件类型；MS-DOS 曾限3字符。

拡張子の対応（マッチング頻出）：.txt=テキスト、.mp3=音声、.pdf=ドキュメント、.html=WWW文書、.jpg=静止画、.mpg=動画、.c=C言語ソースプログラム、.gif=画像。

レコードとブロック

レコードrecord ファイルは互いに関連した項目からなる論理レコード（logical record）の集まり。ディスクから読み書きする単位を物理レコード（physical record）という。 记录：文件由「逻辑记录」组成；实际读写单位是「物理记录」。
ブロックblock レコードの集合。記憶装置上の読み書きの単位。関連語：非ブロックレコード（1ブロックに1論理レコード）／ブロックレコード（1ブロックに複数）／固定長・可変長レコード／インターレコードギャップ（ブロック間の間隙）。 块：记录的集合，是设备读写单位。块间空隙叫 inter-record gap。

ファイル操作と制御

ファイル操作の順序：生成(Create,初回のみ) → オープン(Open) → 読み書き(Read/Write) → クローズ(Close) → 削除(Delete,最終回のみ/不要時)。代表的システムコール：Create/Delete, Open/Close, Read/Write, Append など。
ファイル制御ブロックFCB: File Control Block ファイル情報を読み込むメモリ領域（基本的にMS-DOS用語）。位置・レコードサイズ・アクセス方法などを含む。複数のFCBの確保が可能で、確保された数だけファイル操作を同時実行できる。 读入文件信息的内存区域；可分配多个 FCB，能同时操作多个文件。
ファイル記述子file descriptor ファイルを識別する情報。ファイルオープンのシステムコールの戻り値（非負の整数）で、オープンファイルテーブル（FCB）のインデックスとなる。標準入力0/標準出力1/標準エラー出力2、最初に開くファイルは3。 文件描述符：open 系统调用的返回值（非负整数），是打开文件表的索引。0/1/2 为标准输入/输出/错误。
ブロッキングとバッファリングblocking / buffering レコードをブロックに組み立て（ブロッキング）・分解（デブロッキング）する。ダブルバッファリングによりデータ転送とCPU処理を並列に行う（「直列」は誤り）。 成块/拆块；双缓冲让传输与CPU处理「并行」（不是串行）。

UNIX とシステムコール

システムコールsystem call OSのカーネルを外部から呼び出すインタフェース（例：write(), read(), open()）。標準ライブラリ関数（printf(), scanf() 等）はカーネル処理を使うものと使わないものがある。 系统调用：从外部调用内核的接口；标准库函数有的用内核有的不用。

UNIXのファイル3種：通常ファイル（テキスト/バイナリ）、スペシャルファイル（デバイスファイル）、ディレクトリ。UNIX標準＝POSIX。

L10 ファイルシステム(2)：ディレクトリ・保護・割付け Directory

ディレクトリdirectory ファイルの台帳・登録簿。2次記憶上の全ファイルの情報を保持（ファイルそのものは含まない）。ディレクトリ自体も2次記憶上に保持（常に主記憶上ではない）。ファイルアクセスに先立ってディレクトリアクセスが必要。 目录：文件的台账，保存所有文件的「信息」（不含文件本身）；目录本身也在二级存储。

ディレクトリに保管される情報：名前・型・サイズ・構造や保護の情報・2次記憶上のアドレス（主記憶上ではない）・作成日時・更新日時・読出し/書込み回数。

ディレクトリの構造：linear list（線型リスト）＝線型探索、構造が簡単、作成・削除容易だがリンク格納領域が必要／hash table＝検索時間短い・挿入削除簡単だがファイル名の衝突あり／binary tree。

探索アルゴリズム（計算が出る）

算法说明・计算
線型探索
linear search		端から順番に探す。1件チェックにp秒、総数n個なら最悪 np秒。
例：100万件×0.05μs＝… 平均は半分。1000万×… 練習で計算を確認。
二分探索
binary search		ソート済みデータが前提。中央値と比較して区間を半分に絞る。10件なら最大3回（1回目で5個、2回目で3個、3回目で1個除外）。
ハッシュ探索
hash search		ハッシュ関数で格納位置を計算。もとの数をキー(key)、返る値をハッシュ値という。例：ハッシュ関数＝7で割った余り、キー51 → 51=7×7+2 → ハッシュ値 2。

ディレクトリの階層化

ファイル数増加の問題（検索時間増、ディレクトリ自体のサイズ増、2次記憶アクセス増）を解決するため階層化。2階層ディレクトリ（マスタファイルディレクトリ＋ユーザディレクトリ）→ 共有が△。木構造ディレクトリ（tree structured directory）＝サブディレクトリで共有を実現、Windows/Linuxで採用。ディレクトリのサイズはファイルの個数で決まる（サイズではない）。

パス名：完全パス名（complete path）＝ルートから全ディレクトリ名を連結／相対パス名（relative path）＝カレントディレクトリから連結。

ファイル保護

ファイル保護file protection 不当な操作からの保護＝アクセス制御（access control）、物理的障害からの保護＝バックアップ（backup）と回復（recovery）。 文件保护＝访问控制（防非法操作）＋备份/恢复（防物理故障）。
アクセス制御：①アクセス制御行列（ユーザ×ファイルで OK=1/NG=0）②ユーザクラス（user class）：所有者(owner)・グループ(group)・共有(public)。UNIXは各クラスに3ビット＝rwxビット（r=read, w=write, x=execute）。
ミラーリング（mirroring）＝ディスクを2重化し両方に書く（物理障害対策）。

L11 割込みと入出力の制御(1)：割込み Interrupt

割込み処理interrupt ある要因（入出力完了・タイマ満了・エラー発生など）が発生したとき、通常のルーチンワークを抜けて該当処理を行い、その後もとに戻ること（OSの仕事）。C言語では関数として記述する。 中断：某事件发生时暂离常规流程去处理，处理后返回。
割込みの種類
・外部割込み（ハードウェア割込み）：外部からCPUへ。入出力装置・タイマ・ユーザ操作/センサなど。割込みベクタ方式で処理。
・内部割込み（ソフトウェア割込み）：実行中プログラムが発生。システムコール割込み、プログラム例外（オーバーフロー・0除算・書込み禁止領域への書込み）、ページフォールト割込み（主記憶に無いページ参照）など。
外部=硬件（I/O、定时器、传感器…）；内部=软件（系统调用、异常、缺页）。

割込みの処理方式（3つ）

方式特徴
他の全ての割込みを禁止実現が容易・オーバーヘッド少。但し割込み処理中に他の割込みに対処できず、割込み消失の危険（※「難しく大きい」は誤り）。
割込みに優先度を設定ネスト（nesting：入れ子）を行う。低優先は待たせ、高優先は実行し現在の処理を中断。利点＝処理が速い、問題＝ネストのオーバーヘッド。
割込みの一部をプロセスとする他の割込みに対処可能。問題＝メッセージ送受信のオーバーヘッド。
割込みハンドラinterrupt handler 割込みを処理・制御するためにメモリ上に待機しているプログラム。割込み発生時に原因を解析し、対応する処理ルーチンへ制御を移す。割込みコントローラ（複数割込みの交通整理を行うハードウェア）とは別物。 中断处理程序：常驻内存、分析中断原因并转到相应例程。别与「中断控制器（硬件）」混淆。

割込みハンドラの構成法：①分岐先アドレスが固定 → ハンドラが要因解析／②ベクタテーブル → 割込みベクタテーブルのエントリにジャンプ（分岐命令が格納）。
割込みベクタ（Interrupt Vector）＝割込みの方向を示すもの。流れ：割込み(要求元→CPU)①→応答(CPU→要求元)②→割込みベクタ通知(要求元→CPU)③→ベクタテーブル検索・処理ルーチンアドレス取得(CPU)④→割込み処理実行⑤。

割込みの許可と禁止

割込み禁止フラグ（0=禁止, 1=可）と割込みマスク（優先度順のビット列、0=有効/1=無効、境界＝マスク閾値）の2つを使う。
用「中断禁止标志」和「中断掩码」两者控制许可/禁止。

割込み処理の流れ（順序頻出）：1.受付可否を決定 → 2.フラグをリセットし全割込み禁止 → 3.退避用スタックに処理途中の情報をプッシュ → 4.フラグをセットし許可状態に → 5.処理ルーチンに分岐 → 6.終了後に当該割込みの無効化を解除 → 7.ネストされていればスタックをポップして回復し続きを実行。一度割込みコンテキストに入ると最後の割込みが終わるまでユーザプロセスは実行されない。

シグナルsignal UNIX系OSで、プロセス間通信の形式でプロセスに非同期にイベント発生を通知するもの。割込みの抽象化（外部・内部割込みを統一的に扱う）。受信時の処理をシグナルハンドラとして書ける（例：signal(SIGINT, ...)）。 信号：UNIX 中异步通知进程事件，是「中断的抽象化」；处理函数叫信号处理程序。

L12 割込みと入出力の制御(2)：入出力 I/O Control

入出力操作 / 入出力制御I/O operation / control 入出力操作＝入出力装置と主記憶の間でデータ転送を行うこと。入出力制御＝各プロセスに入出力装置を割り付け、共有を管理し、システム全体で効率よくスケジューリングすること。入出力装置を仮想化し一様なインタフェースを提供する。 I/O操作=设备与主存间传数据；I/O控制=分配设备、管理共享、统一调度、虚拟化设备。
デバイスの種類：ブロック型デバイス（block device）＝ブロック単位で読み書き（ハードディスク・CDROM・USBメモリ）／文字型デバイス（character device）＝文字単位（プリンタ・マウス・キーボード・ネットワークインタフェース）。
块设备：HDD/CDROM/U盘；字符设备：打印机/鼠标/键盘/网卡。
デバイスドライバdevice driver 装置や機器を制御・操作するためのソフトウェア。OSが機器を制御するための橋渡し。抽象化・共通化されたインタフェースを提供。デバイスごとに存在する。 设备驱动：控制设备的「软件」，OS 与设备的桥梁；每种设备各有其驱动。
デバイスコントローラdevice controller 入出力装置と主記憶の間でデータの仲介を行う装置（ハードウェア＋ファームウェア）。デバイスごとにあり、ドライバの指示で動く。レジスタを持ちCPUと通信。※「ソフトウェア」ではない。 设备控制器：介于设备与主存的「硬件+固件」，含固件的硬件（不是软件）。

チャネル（channel）＝入出力専用のプロセッサ。コマンドプログラム / チャネルプログラム＝デバイスコントローラを制御する命令コマンド系列（シーク＋回転＋読出し等）。制御方式：メモリマップ型入出力（memory-mapped I/O）（レジスタがアドレス空間の一部）／コントローラが自らコマンドを取り出す方式。

DMADirect Memory Access デバイスコントローラがデータ転送を行い、CPUは入出力動作を起動するだけ。高速なブロック型デバイスで使用。※CPUが直接転送する方式はプログラム方式の入出力（programmed I/O）。 DMA：由控制器传数据，CPU 只启动。CPU 亲自传的是 programmed I/O。

同期/非同期・バッファリング・スプーリング

用語説明
同期入出力
synchronous I/O		入出力要求後、完了の割込みが入るまで待つ（通常の方法）。
非同期入出力
asynchronous I/O		要求後すぐ制御権が返る。別のことができるが、プロセス側で完了との同期を取る必要。
バッファリング
buffering		バッファ（buffer）＝緩衝域。CPUと入出力装置を常に動作状態にする仕掛け。バッファはコンピュータ内部、置いた後操作できない場合あり。
スプーリング
spooling		SPOOL＝Simultaneous Peripheral Operation On Line。記憶装置（内部HDD）で機器を並列動作。特定プロセスの長時間占有を防ぐ。置いた後も操作可能（例：削除）。プリンタ出力など。
よくあるひっかけ：「スプーリング」と「バッファリング」の説明の入れ替え。スプーラは内部/外部どちらもあり得るのはバッファの話。buffer 在内部；spooling 用内部HDD、放入后仍可操作（可删除）。二者说明常被互换考。

DCB（Device Control Block）＝入出力装置を管理するテーブル（装置ごと）。cf. PCB(プロセス制御ブロック)・FCB(ファイル制御ブロック)。IRB（I/O Request Block）＝入出力要求の情報（要求ごと、キューを構成）。
タイマ管理：時刻維持（UTC）、プロセスの時間制限、CPU使用の会計、監視。watchdog timer（番犬）＝プロセスや入出力装置の監視を行うタイマ。

L13 マルチメディアOS Multimedia OS

マルチメディアmultimedia コンピュータ上で文字・静止画・動画・音声など様々な形態の情報を統合して扱うこと。単なる統合でなく、利用者の操作に応じて表示・再生が変化する双方向性（インタラクティブ性）を重視する考え方もある。 多媒体：统合处理文字/图/视频/音频；强调交互性（双向性）。
マルチメディアの要求：①大量の情報 ②極めて速いデータ ③実時間再生。※「無制限にアクセス可能」はマルチメディアとは無関係（ひっかけ）。VOD（Video On Demand）＝観たい時に映像を視聴できるサービス（マルチメディアOSが最も要求される）。
要求：大容量、高速、实时再生。VOD 最需要多媒体OS。
マルチメディアファイルmultimedia file 音声ファイルと映像ファイルから構成。音声と映像の同期をlip synchronization（リップシンク）という。音声は複数トラック（オリジナル音声[原語/音楽・効果音]、副音声[吹替え]、字幕[原語/翻訳]）。 多媒体文件=音频+视频；音画同步叫 lip synchronization。
圧縮説明
静止画：JPEGRGB（三原色＝赤 Red・緑 Green・青 Blue、※黄色ではない）。1画素(pixel)＝8bit×3＝24bit。輝度(luminance)には敏感・色差(chrominance)には鈍感 → 色差を粗く。離散コサイン変換（DCT）でさらに圧縮。
動画：MPEG基本情報＋予測情報。Iフレーム（Intra-coded：JPEGを定期取得）／Pフレーム（Predictive：過去から予測、差分送信）／Bフレーム（Bidirectional：過去と未来から予測）。音声は音響心理学に基づく符号化（大きな音に隠れる小さな音は聞こえない）。

リアルタイムスケジューリング

リアルタイムOS＝決められた時間内に処理完了を保証・重視するOS。マルチメディアOSは従来OSと①プロセススケジューリング②ファイルシステム③ディスク割付け・スケジューリング で異なる。
スケジューリング可能条件：Σ(Cᵢ/Pᵢ) ≤ 1（Pᵢ=周期/納期、Cᵢ=1回のCPU時間）＝CPU使用率。
方式説明
RMS
Rate Monotonic Scheduling
（優先度固定）		優先度を固定して切り替え。横取り可能（preemptive）。優先度＝頻度（周波数、周期が短いほど高優先）。単純で実装しやすい。※「横取り不可能」は誤り。
EDF
Earliest Deadline First
（納期優先）		納期が近いプロセスを優先。横取り可能。CPU使用率100%が可能。RMSで不可でもEDFなら可能な場合がある。但しアルゴリズムが複雑。
push server / pull server マルチメディアファイルシステムではpush serverを使う（startで一定間隔送信、stopで停止）。従来型はpull server（ユーザが一定間隔でreadを発行）。 多媒体文件系统用 push server（服务器主动定时推送）；传统是 pull server。

ディスクスケジューリング：FCFS（First-Come-First-Served、要求順、効率悪い）／SSF（Shortest Seek First、近い場所から、混むと中央に張り付く）／エレベータアルゴリズム（方向を変えず処理）。マルチメディア用は納期優先のscan-EDF（納期の近い要求をセットにし、セット内は物理アドレス順）。

L14 OSと仮想化技術 Virtualization

仮想化virtualization 実際には存在しないものをあたかも存在するように、あるいは実際とは違う形で見せること。コンピュータでは、リソースや処理を抽象化してユーザ・プログラムに見せること。1960年代からある古い考え方（最近生まれたものではない）。 虚拟化：把不存在的东西显示成存在，或以不同形式呈现；抽象化资源。1960年代就有。
OSにおける3つの仮想化：①処理（プログラムとCPU）の仮想化＝プロセス ②記憶（メモリ）の仮想化＝仮想アドレス ③情報（データ）の仮想化＝ファイル。「OSの歴史は仮想化の歴史」。
OS 三大虚拟化：进程（处理）、虚拟地址（内存）、文件（信息）。

従来のマルチコンピュータ環境（役割別の複数物理マシンを高速ネットで接続）：利点＝性能（負荷分散）・信頼性・セキュリティ向上（一台の故障/攻撃が波及しない）。課題＝機器コスト・物理スペース・電力等の維持コスト。→ 仮想化技術で一台に複数の独立環境を構築し課題を解決。

ハイパーバイザ

ハイパーバイザhypervisor タイプ1（Type 1）：ハードウェアとOSの間にソフトウェア階層を追加（ハードウェア直上）。タイプ2（Type 2）：ベースとなるOS（ホストOS）のアプリケーションとしてインストール。ゲストOSの下位層にホストOSがある（逆ではない）。 Type1：直接在硬件上；Type2：作为宿主OS上的应用安装。宿主OS(host)在客户OS(guest)之下。

歴史：IBMのVM/370（対話型OS＝CMS: Conversational Monitor System を乗せる）、後継 z/VM。PCでは1998年 VMware社創立。インテルCPU(x86)は仮想化対応が遅れた（PopekとGoldbergの要件を満たさず、2005年に対応）。

Popek と Goldberg の仮想化要件virtualization requirements ①等価性/安全性（資源管理）②忠実性（Fidelity）：仮想マシン上のプログラムは実ハードウェア上と同じように動く ③効率性（Efficiency）：ハイパーバイザの介入で性能低下しない。忠実性の必要条件＝センシティブ命令セットは特権命令セットの部分集合でなければならない。センシティブ命令＝カーネル/ユーザモードで振舞いが異なる命令、特権命令＝ユーザモードで実行するとカーネルモードへ移行する命令。 虚拟化三要件：等价/忠实性(Fidelity)/效率性(Efficiency)。忠实性条件：敏感指令⊆特权指令。

実アドレスの仮想化：ゲストOSには実アドレスが見えねばならず、複数VM同居には仮想実アドレスが必要（ハイパーバイザが変換）。実入出力装置も同様に仮想化。

仮想マシンの利用：仮想アプライアンス（Virtual Appliance）＝動作環境＋アプリのセット。クラウド（Cloud）：IaaS(Infrastructure as a Service＝コンピュータ環境)／PaaS(Platform＝開発環境)／SaaS(Software＝ソフトウェア)。利点＝自前ITインフラ不要・従量課金。心配＝セキュリティ・信頼性。
云：IaaS(基础设施)/PaaS(平台/开发环境)/SaaS(软件)。
